DESIPATH Immigration News Module Complete Technical Specification v1.0 Document Version 1.0 — May 2026 Module Name Desipath Immigration News Purpose Daily active users — no direct revenue generation Core Technology AI-powered curation using Claude API (Anthropic) Architecture Automated crawl → AI filter → AI summarise → auto-publish Running Cost Under $25 per month total infrastructure Audience Product · Engineering · DevOps 1. Overview The Desipath Immigration News module is a fully automated, AI-curated news digest that aggregates immigration news from 15–20 trusted sources, filters for NRI relevance using Claude AI, rewrites each article as a plain-English summary for Indian-American readers, and publishes the digest to Desipath automatically — with zero manual content effort after initial setup. The module exists purely to drive daily active users. Immigration news is the single most urgency-driven content category for NRI professionals in the USA — H-1B policy changes, visa bulletin updates, premium processing suspensions, and Green Card priority dates directly affect NRIs lives. A user who gets a push notification about a USCIS policy change will open Desipath immediately. That habit of daily checking is the goal. Design Principle: Desipath is a curator, not a publisher. Every article links back to the original source. Desipath adds value through: NRI-specific relevance filtering, plain-English summarisation optimised for busy Indian-American professionals, and urgency classification that tells users what needs their attention today vs what can wait. Legal Note: Desipath publishes AI-generated summaries of news articles with prominent attribution and links to original sources. This is consistent with established fair use doctrine for news aggregators (see Google News, Apple News, Feedly). Desipath does not reproduce full article text. All summaries are transformative AI-generated content, not copies. 2. AI Pipeline Architecture — Complete Flow The pipeline runs as a scheduled background job. No human action is required for normal operation. The pipeline ingests raw articles, passes them through three sequential Claude API calls, and publishes approved articles to the Desipath immigration news feed. Pipeline Stage Input AI Model Output Error Handling Stage 0: Crawl RSS feeds + web scrapers No AI — raw HTTP Raw article objects in pending_queue table Retry 3x with exponential backoff. Log failures. Skip and continue on persistent failure. Stage 1: Relevance Filter Raw article text (title + body excerpt) Claude Haiku (fast, cheap) JSON: {score: 0-10, is_relevant: bool, reason: string} If API error: mark as pending_retry. After 3 failures: send to manual_review queue. Stage 2: Summarise &amp; Categorise Full article text Claude Sonnet (higher quality) JSON: {headline, summary, category, tags[], urgency, nri_angle} If API error: retry 2x. If fails: send to manual_review queue with original article. Stage 3: Quality Check AI-generated summary + original title Claude Haiku (fast) JSON: {decision: pass/review/reject, flags[], reason} If API error: default to review (not auto-publish). Safety-first on errors. Stage 4: Publish Approved article data No AI — DB insert immigration_news row inserted. Push notification fired if urgency = high. If DB insert fails: retry 3x. Alert admin if persistent failure. 3. Playwright npm package for JavaScript-rendered scraper targets. Cheerio for static HTML scraping. Schedule Cron job: 0 */3 * * * (every 3 hours, 24/7). Eight crawl cycles per day. GitHub Actions scheduled workflow is a free alternative for low-frequency crawling. Deduplication Before processing any article: compute MD5 hash of (source_url + headline). Check against news_dedup_hashes table. If hash exists AND was ingested within 7 days: skip. Insert hash on first ingest. This prevents the same story from 5 sources all appearing in the feed. Rate limiting Minimum 1000ms delay between requests to the same domain. Respect robots.txt — check on first crawl per domain and cache for 24 hours. Maximum 3 concurrent requests globally (not per domain). Article body extraction Use Mozilla Readability algorithm (npm: @mozilla/readability) to extract main article text from full HTML. This strips navigation, ads, and sidebars, leaving only the article body. Pass the cleaned body to Stage 1. Minimum article length Skip articles with body text under 100 words after Readability extraction. These are usually stub pages, paywalled articles, or navigation pages mistakenly scraped. Paywall handling If article body is under 150 words but title and excerpt are present: use title + excerpt only for AI processing. Mark as paywall_suspected = true. Summary will be based on available excerpt only. Source health monitoring Track per-source success rate. If a source returns errors &gt;5 consecutive times: send admin email notification. Disable the source temporarily and set next_retry_at = now + 24 hours. Storage of raw articles Raw articles stored in news_raw_queue table with status = pending. Processed articles retain a foreign key to the raw row for audit trail. 4. Stage 1 — AI Relevance Filter 4.1 Claude API Call Specification Parameter Value Model claude-haiku-4-5 (fastest, cheapest — sufficient for binary classification) Max tokens 150 (only needs a short JSON response) Temperature 0 (deterministic — same article should always get the same score) System prompt See Section 4.2 below Input Article title + first 500 words of body text (truncated to reduce token cost) Expected output format JSON: {&quot;score&quot;: 7, &quot;is_relevant&quot;: true, &quot;reason&quot;: &quot;H-1B fee increase directly affects NRI IT workers&quot;} Cost per call Approximately $0.0003 per article at Claude Haiku pricing Relevance threshold is_relevant = true if score &gt;= 6. Score &lt; 6: article discarded. 4.2 Stage 1 — System Prompt (Exact Text) You are a news relevance classifier for Desipath, an NRI community platform serving Indian-Americans in the USA and Canada. Evaluate if the provided article is relevant to Desipath users. Relevant topics include: - US immigration: H-1B, H-4, L-1, O-1, EB visas, Green Card, PERM - USCIS policy changes, processing times, fee changes - US State Department: visa bulletins, passport, OCI card - Indian-American (NRI) community news and policy impacts - Student visas: F-1, OPT, CPT, STEM OPT - Immigration court decisions affecting NRI professionals - India NRI policies: OCI rules, NRE/NRO banking changes - Travel bans, country-specific visa changes affecting Indians NOT relevant (score 0-3): - General US politics with no immigration angle - Sports, entertainment, technology (unless immigration-related) - Immigration news about non-Indian populations only - Opinion pieces with no factual policy content Return ONLY valid JSON, no other text: {&quot;score&quot;: &lt;0-10&gt;, &quot;is_relevant&quot;: &lt;true/false&gt;, &quot;reason&quot;: &quot;&lt;one sentence&gt;&quot;} Exception rule: Articles from USCIS.gov, travel.state.gov, and federalregister.gov (official government sources) always receive is_relevant = true and score = 10, regardless of AI output. These are hardcoded overrides in the application logic — do not pass government source articles through the relevance filter. 5. Stage 3 — AI Quality Check 6.1 Claude API Call Specification Parameter Value Model claude-haiku-4-5 (fast, sufficient for binary pass/review/reject decision) Max tokens 200 Temperature 0 (deterministic moderation decisions) Input AI-generated headline + AI-generated summary from Stage 2 (not original article) Expected output JSON: {&quot;decision&quot;: &quot;pass&quot;, &quot;flags&quot;: [], &quot;reason&quot;: &quot;Clean factual news&quot;} 6.2 Stage 3 — System Prompt (Exact Text) You are a content moderator for Desipath, an NRI community platform. Review the following immigration news summary and decide if it is safe to publish automatically. Flag for human review (decision = &quot;review&quot;) if: - The summary contains legal advice (telling readers what they should do legally) - The content is politically inflammatory or attacks specific politicians - There are misinformation signals (extraordinary claims without sources) - The summary mentions specific dollar amounts for legal fees or immigration costs in a way that could mislead readers - The content could cause panic in the NRI community without solid basis Reject automatically (decision = &quot;reject&quot;) if: - The content is about criminal immigration violations or deportation horror stories presented in a sensationalist way - The summary appears to be advertising or sponsored content disguised as news - The content contains conspiracy theories about immigration policy Approve (decision = &quot;pass&quot;) if: - The summary is factual, clear, and relevant to NRI immigration topics - The tone is neutral and informative Return ONLY valid JSON: {&quot;decision&quot;: &quot;pass|review|reject&quot;, &quot;flags&quot;: [&quot;&lt;flag1&gt;&quot;, &quot;&lt;flag2&gt;&quot;], &quot;reason&quot;: &quot;&lt;one sentence&gt;&quot;} Safety default: If the Stage 3 API call fails or returns an unparseable response, the article defaults to decision = &quot;review&quot; and is sent to the human moderation queue. Never auto-publish on API errors. 7. Data Model — Complete Schema 7.1 news_raw_queue Stores every article collected by the crawler before AI processing. Provides a complete audit trail. Step-by-Step Implementation Guide This section provides the exact sequence of implementation steps for the engineering team. Each step is a discrete, testable unit of work. Follow the sequence — later steps depend on earlier ones. Acceptance Criteria # Acceptance Criterion AC-01 The cron job crawls all configured RSS and web scraper sources every 3–4 hours without manual intervention. A crawl run completes in under 10 minutes for 150 articles. Failed source crawls are logged but do not stop the overall run. AC-02 Articles from USCIS.gov, travel.state.gov, and federalregister.gov always receive is_government_source = true and skip the Stage 1 relevance filter entirely. They are always processed through Stages 2 and 3. AC-03 The deduplication system correctly prevents the same article (same source_url + headline combination) from being processed and published more than once within any 7-day window. AC-04 Stage 1 correctly classifies at least 80% of test articles (measured on a manually labelled test set of 50 articles — 25 relevant, 25 not relevant). Government sources always pass regardless of score. AC-05 Stage 2 summaries are 3–5 sentences, do not contain jargon without explanation, reference the NRI/Indian-American context at least once, and do not make up information not present in the original article. Verified by manual review of first 50 published articles. AC-06 Stage 3 quality check correctly flags articles containing legal advice language (&quot;you should file&quot;, &quot;you must apply&quot;, &quot;contact a lawyer immediately&quot;) for human review rather than auto-publishing them. AC-07 On any Stage 3 API error or unparseable response, the article defaults to decision = review and is added to the manual review queue. It is never auto-published on an API error. AC-08 The admin review queue email is sent when the queue reaches 3+ pending items. Email contains article headlines, flag reasons, and a direct link to the admin review page. Maximum 2 admin alert emails per day. AC-09 High-urgency push notifications are delivered within 30 minutes of article publication. Maximum 2 push notifications per user per day regardless of how many high-urgency articles are published. AC-10 Every article card and detail page displays: source name, &quot;Source:&quot; label, original publication date, and a prominent &quot;Read full story at [source name]&quot; link to the original URL. These elements cannot be removed or hidden. AC-11 The attorney module cross-link (&quot;Find an NRI immigration attorney&quot;) is displayed on all articles where attorney_referral = true. The link filters the attorney module to immigration practice area. AC-12 The disclaimer text (&quot;AI-generated summary... not legal advice&quot;) is displayed on every article card and every article detail page. It cannot be hidden. AC-13 Three user reports on any published article automatically set status = unpublished and send an admin notification. The article is removed from the public feed immediately on the third report. AC-14 The daily digest email is sent at 8:00 AM ET ± 5 minutes. The weekly summary is sent on Sunday at 10:00 AM ET ± 5 minutes. Both use the existing Desipath email infrastructure and honour user unsubscribe preferences. AC-15 The news feed page loads in under 2 seconds (P95) with 20 articles displayed. Article detail page loads in under 1.5 seconds. Both tested on mobile (3G simulation in Chrome Lighthouse).
