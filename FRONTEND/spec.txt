1. Overview

DesiPath is an NRI-focused community platform serving the ~8.4 million Indian diaspora in the US and Canada. The SecureMatch matrimonial module extends the platform with a privacy-first, consent-gated matchmaking system designed specifically for the global Indian diaspora. This document defines the full technical specification covering architecture, data models, APIs, security, integrations, and infrastructure required to design, build, and operate the module.

1.1 Problem Statement

Existing matrimonial platforms (Shaadi.com, BharatMatrimony) were designed for India-based users and bolt on NRI support as a filter. They expose photos and personal identity by default, have no meaningful NRI credential verification, and do not support the cross-border trust requirements that NRI matches demand. The result is low female engagement, high fake-profile rates, and poor match quality for diaspora users.

1.2 Solution Summary

SecureMatch inverts the default: identity is private until both parties consent. Profiles are discoverable but anonymous. A mutual accept mechanism gates progressive information disclosure. NRI-specific verification (visa status, country of residence, employment) builds trust without invasive data collection.

1.3 Key Differentiators

Privacy-first: Photos and personal details hidden by default

Consent-gated: Mutual acceptance required before profile unlock

NRI-verified: Residency tier and immigration status verification

Family Circle: Read-only family portal for parental involvement

Voice-first: Voice note introduction before photo unlock

AI Compatibility: Values-based scoring, not photo-based

Masked Video: AR face blur on video calls before trust is established

3.2 Consent Flow

Step 1 — Discovery: User A browses anonymous profiles. No photos or names visible or Not based on User.

Step 2 — Interest: User A sends interest request to User B.

Step 3 — Review: User B sees User A's anonymous profile. Accepts or declines.

Step 4 — Unlock: On mutual accept, both profiles unlock progressively. Photos first, then contact details.

Step 5 — Connect: Messaging enabled. Video calling available with optional face blur.

8. Security & Compliance

8.1 Data Security

All messages encrypted at rest using AES-256

Photos served via signed Azure CDN URLs (expiry: 1 hour)

Photo watermarking: viewer user ID embedded invisibly in every photo delivery

Voice notes encrypted at rest, served via signed URLs

Personal fields encrypted in database (field-level encryption for contact details)

TLS 1.3 enforced on all endpoints
